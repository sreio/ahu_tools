# Workbench UI Experience Design

## Goal

优化 AhuTools 当前工具页的使用体验，让高频工具能更快进入输入、执行、查看结果、复制结果的闭环，同时保持多工具扩展时的导航清晰度。

本次设计采用“工作台布局”：左侧负责工具切换，顶部负责全局快捷动作，主体区域按当前工具展示输入、结果和上下文操作。

## Current Friction

从现有页面和工具实现看，主要问题是：

- 工具入口依赖左侧分组和滚动，工具增多后查找成本会上升。
- 每个工具的历史、配置、执行、复制位置不够统一，用户需要扫视页面找按钮。
- 输入在上、结果在下，长文本时容易上下滚动，结果复制不够顺手。
- JSON、JWT、Query 等工具按钮较多，不能简单套用一排固定按钮。

## Design Direction

采用 B 方案：工作台布局。

### App Shell

- 左侧保留工具导航，但视觉更轻，突出当前工具。
- 顶部增加工作台工具栏，承载：
  - 当前工具标题。
  - 工具搜索或快速跳转。
  - 历史。
  - 当前工具配置入口，如数据解密环境配置、H5 配置。
  - 应用级设置入口。
- 主体区域使用输入面板和结果面板，尽量减少整页滚动。

### Main Workspace

默认在宽屏下使用左右两栏：

- 左侧：输入、参数、主执行动作。
- 右侧：结果、复制、结果视图切换。

输入和结果内容区独立滚动。关键操作按钮不放进滚动内容里，避免长文本遮挡。

窄窗口下改为上下堆叠：

- 输入面板在上。
- 结果面板在下。
- 每个面板自己的头部操作栏仍保持可见。

## Action Placement Rules

工作台布局不能把所有按钮都塞进同一位置。按钮按上下文和频率分层。

### Global Actions

放在顶部工作台工具栏：

- 历史。
- 配置。
- 工具搜索。
- 应用设置。

这些动作会打开 drawer、dialog 或 popover，不属于输入或结果本身。

### Input Actions

放在输入面板头部或输入面板底部的 sticky action bar：

- 执行主动作，如解密、格式化、生成、解析。
- 输入清空。
- 输入复制。

输入内容可以滚动，但主执行动作必须保持可见。

### Result Actions

放在结果面板头部：

- 复制结果。
- 清空结果。
- JSON/Raw、Header/Payload 等结果视图切换。

结果内容可以滚动，但复制和视图切换必须保持可见。

### Button Density

每个面板默认最多常显 1 到 2 个主按钮。超过后采用：

- 分段控件或 tabs 切换模式。
- 更多菜单收纳低频动作。
- 行级操作留在行内。

## Tool Adaptation

### Data Decrypt and H5 Decrypt

- 输入面板：环境选择、模式选择、密文输入、解密按钮。
- 结果面板：JSON/Raw tabs、复制结果、清空结果。
- 配置和历史放顶部工具栏。

### JSON

JSON 是按钮密度最高的工具之一。

- 常显主动作：格式化、压缩。
- 结果动作：复制输出、替换输入。
- 更多菜单：中文转 Unicode、Unicode 转中文、添加反斜杠、去除反斜杠。

这样避免 6 到 7 个按钮占满工具栏。

### Base64, URL, HTML Entity

- 使用输入面板常显 Encode、Decode。
- 结果面板放复制输出。
- 清空输入可作为次动作。

### JWT

JWT 属于复杂模式工具。

- 顶部或面板内使用分段控件区分“解码/验签”和“签名生成”。
- 解码/验签模式只显示解码、验签、复制 Token。
- 签名生成模式只显示生成 Token、复制 Token、清空。
- Header、Payload、Signature 的复制可以保留在各自结果块内，或者通过结果面板“更多”统一收纳。

### Query

Query 属于列表编辑工具。

- 输入面板：解析、添加参数、构建 Query。
- 行级删除按钮保留在参数行内。
- 结果面板：复制输出。

### Timestamp, Random, Hash, Regex

这些工具按钮较少，可直接使用工作台标准模式：

- 输入面板显示参数和主动作。
- 结果面板显示结果和复制。

## Components

建议通过通用布局组件减少重复：

- `WorkbenchShell`
  - 渲染顶部工具栏和当前工具主体区域。
  - 管理工具搜索、历史、配置入口。

- `ToolWorkspace`
  - 提供左右两栏和窄屏堆叠布局。
  - 支持 `input`、`result`、`toolbar` slots。

- `ToolPanel`
  - 面板容器。
  - 支持 title、primary actions、secondary actions、footer/status。
  - 内容区默认独立滚动。

- `ActionOverflow`
  - 收纳低频操作。
  - 用于 JSON 等按钮密集工具。

如果 Vue 单文件组件过多导致迁移成本高，可以先只创建 `ToolPanel` 和共享 CSS class，再逐步迁移每个工具。

## Migration Strategy

分阶段落地，避免一次性重写所有工具：

1. 先改 App shell：
   - 添加顶部工作台工具栏。
   - 统一历史、配置、设置入口。
   - 左侧导航保留现有数据和排序逻辑。

2. 建立通用面板样式：
   - 输入/结果面板。
   - sticky action bar。
   - 独立滚动内容区。
   - 响应式上下堆叠。

3. 迁移高频工具：
   - 数据解密。
   - H5 数据解密。
   - JSON。

4. 迁移按钮复杂工具：
   - JWT。
   - Query。

5. 迁移低复杂工具：
   - Base64、URL、HTML Entity、Timestamp、Random、Hash、Regex。

## Error Handling

- 表单校验和业务错误仍显示在当前工具面板内。
- 错误提示不应挤占顶部工具栏。
- 长错误可以放在输入面板或结果面板的状态区。
- 执行失败时结果面板可以展示错误状态，但不能隐藏输入面板主动作。

## Testing

### Layout Tests

扩展现有 `frontend/src/layout.test.js`，覆盖：

- 工具卡片或工作台容器宽度能填满主区域。
- 输入/结果面板使用独立滚动容器。
- 面板头部操作栏不在滚动内容内部。
- 窄屏下工作台变为单列堆叠。

### Tool Behavior Tests

保留现有工具纯函数测试。

对迁移后的高风险工具补充组件级或结构测试：

- JSON 常显按钮不超过设计限制，低频按钮进入更多菜单。
- JWT 不同模式只显示当前模式相关按钮。
- Query 行级删除仍在参数行内。

### Manual Verification

- 数据解密长文本输入时，解密按钮始终可见。
- 长 JSON 结果时，复制按钮始终可见。
- 小窗口下输入和结果上下堆叠，不出现按钮遮挡。
- 左侧收起和展开时，主体区域仍自动填充。

## Acceptance Criteria

- 用户可以通过左侧或顶部搜索快速切换工具。
- 高频工具能在同一屏完成输入、执行、查看结果、复制结果。
- 长输入和长结果不会遮挡主操作按钮。
- JSON、JWT、Query 等多按钮工具不会出现按钮溢出或挤压。
- 工具历史、配置、应用设置位置统一。
- 宽屏为左右工作台布局，窄屏为上下堆叠布局。
- 现有工具功能不回退，现有测试继续通过。

## Out of Scope

- 不新增新的业务工具。
- 不改变后端解密、历史、配置、更新逻辑。
- 不引入 Vue Router 或全局状态库。
- 不做完整插件系统。
- 不改变发布版本流程。
